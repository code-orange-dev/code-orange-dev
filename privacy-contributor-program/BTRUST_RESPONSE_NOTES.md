# Btrust Follow-up — Program Response Notes

These notes capture the substantive program changes made in response to the Btrust team's questions.

## 1. Program structure

The Privacy Contributor Program is a new advanced specialization and contributor pathway built on Code Orange's existing foundation programs.

- Workshops/community events are discovery and talent-identification channels.
- Bitcoin Dojo/rawBit provide protocol and transaction foundations.
- Decoding Bitcoin develops general open-source/codebase readiness.
- Participants with equivalent skills can test out of prerequisites.
- The Privacy Program adds privacy engineering foundations, protocol/code labs, contributor rotations and a project residency.
- The strongest contributors can progress into a selective Code Orange fellowship or external funding/grant opportunities.
- Alumni retention support continues through Review Club, contributor calls and mentoring.

The intended learner progression is therefore:

**discover → foundations → contribution readiness → privacy specialization → rotations → residency → fellowship/sustained contribution → mentor/reviewer/maintainer**.

## 2. PRs vs. code review

We agree that the earlier PR-focused framing was too narrow. The revised program makes review and validation first-class contribution modes.

The core contributor loop is:

**READ → BUILD → TEST → REVIEW → CONTRIBUTE → MAINTAIN**.

The program introduces a biweekly Privacy Review Club using real upstream PRs. Participants prepare by checking out branches, building, testing, reading surrounding code/history and producing review notes. As their ability grows, they participate directly in upstream review discussions.

Review development progresses from reproduction/testing to explanation, edge-case analysis, substantive conceptual/code review, and eventually independent recurring review.

Participants who author substantial work are also expected to contribute through review/validation of others' work. We do not require public comments where the participant has nothing useful to add.

## 3. Measuring success

We are moving away from using a target such as '5–8 PRs per graduate' as a headline success measure.

PR authorship remains useful evidence, but we track a broader contribution taxonomy:

- PRs authored/merged;
- substantive PR reviews;
- review discussions;
- PR testing/validation;
- issue investigation/reproduction/resolution;
- tests, fuzzing and benchmarks;
- documentation;
- privacy/protocol research;
- technical communication;
- repeated contribution to the same project;
- increasing independence;
- upstream feedback;
- fellowship/grant/maintainer progression.

The north-star outcome is sustained contribution: whether participants remain meaningfully active in at least one Bitcoin privacy-related open-source project six months after structured training. We also measure activity at 3 and 12 months.

We distinguish outputs (for example, number of reviews) from outcomes (for example, the ability to independently review a medium-complexity change and engage constructively with maintainers).

## Core philosophy

**Our goal is not to optimize for developers who can produce PRs. Our goal is to develop contributors whom upstream projects actually want to keep working with.**
