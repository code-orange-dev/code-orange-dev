# Measurement & Retention Framework

## Why this exists

Raw PR counts are easy to measure and easy to game. The Privacy Contributor Program measures whether participants become useful, increasingly independent, sustained contributors.

## North-star metric

**6-month sustained contributor rate**

Percentage of participants who demonstrate meaningful activity in at least one Bitcoin privacy-related open-source project six months after structured training.

'Meaningful activity' must include evidence beyond passive attendance or repository stars/forks.

## Cohort funnel

Report each stage separately:

1. applicants;
2. admitted;
3. started foundations;
4. contributor-ready;
5. entered rotations;
6. entered residency;
7. completed residency;
8. selected for fellowship;
9. active at 3 months;
10. active at 6 months;
11. active at 12 months.

This avoids treating selective progression as program failure.

## Output metrics

Report by contribution type:

- PRs authored;
- PRs merged;
- PRs meaningfully reviewed;
- review comments/discussions;
- PRs tested/validated;
- bugs reproduced;
- issues investigated;
- issues resolved;
- tests added;
- fuzzing/benchmark work;
- documentation contributions;
- protocol/privacy research artifacts;
- recurring project interactions.

Never combine all activity into a single vanity score.

## Outcome metrics

### Contributor readiness rate
Participant can independently build/navigate/test/review/communicate around scoped upstream work.

### Depth rate
Participant has repeated meaningful interactions with the same upstream project and demonstrates increasing scope/difficulty.

### Upstream usefulness
Qualitative evidence from maintainers/experienced contributors that the participant's work is useful and that continued participation is welcome.

### Independence
Evidence that participant can discover/scout useful work, seek context and move tasks forward without Code Orange assigning every step.

### Retention
Meaningful activity at 3/6/12 months.

### Progression
Fellowships, external grants, recurring reviewer roles, maintainer responsibilities, OSS employment, mentoring and Review Club facilitation.

## 3/6/12 month check

At each checkpoint capture:

- primary project(s);
- contribution evidence since previous checkpoint;
- contribution types;
- current role/area of focus;
- whether work is self-directed;
- upstream relationship status;
- blockers to continued contribution;
- funding/employment status where voluntarily provided;
- next 3-month goal.

## Suggested grant reporting dashboard

### Pipeline
Admissions, progression and residency/fellowship funnel.

### Contribution mix
Distribution across authorship, review, testing, issues, research, docs and maintenance.

### Depth
Number/percentage with repeat contributions to the same project.

### Retention
3/6/12 month contributor rates.

### Upstream signal
Examples of substantive feedback, increasing responsibility and project-requested work.

### Stories
2–4 short case studies showing how contributors moved from learning to independent upstream participation.

## Guardrails

- Do not incentivize comment volume.
- Do not equate merged PR count with contributor quality.
- Do not penalize contributors for working on difficult long-running changes.
- Do not count automated/bot activity.
- Separate learning artifacts from upstream contributions.
- Do not pressure maintainers to provide formal grades.
- Treat upstream feedback as context, not a leaderboard.
- Preserve participant privacy when publishing dashboards.

## Annual program question

At the end of each cohort, Code Orange should be able to answer:

> How many developers became contributors whom real Bitcoin projects wanted to keep working with, and how many were still doing that work six and twelve months later?
