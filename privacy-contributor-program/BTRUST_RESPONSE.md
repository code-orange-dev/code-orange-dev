# Btrust Follow-up Response

Thank you for the thoughtful questions. They helped us sharpen the program around the outcome we care about most: sustained, useful participation in Bitcoin privacy open source.

## Program structure

The Bitcoin Privacy Contributor Program is a new advanced specialization built on Code Orange's existing pathway rather than a replacement for it.

```text
Workshops and community discovery
        ↓
Bitcoin Dojo / rawBit foundations, or competency test-out
        ↓
Decoding Bitcoin / open-source readiness
        ↓
Privacy engineering foundations and protocol/code labs
        ↓
Contributor rotations across 2-3 projects
        ↓
Residency in one primary upstream project
        ↓
Selective Code Orange fellowship, external grants, and sustained contribution
```

Workshops are the broad discovery layer. Bitcoin Dojo and rawBit provide protocol and transaction foundations; Decoding Bitcoin develops codebase navigation and open-source workflow readiness. Developers who already demonstrate those competencies can enter at the appropriate level.

The Privacy Program adds the specialization layer: privacy threat modeling, protocol and implementation study, testing, review, contribution rotations, and a project residency. Its structured instructional portion is intentionally shorter than the old twelve-month course framing. The longer arc is for sustained project work, not for extending classroom time.

## PRs, review, and validation

We agree that the earlier PR-focused framing was too narrow. A pull request is one useful contribution type, not the program's objective.

The core loop is:

> **READ → BUILD → TEST → REVIEW → CONTRIBUTE → MAINTAIN**

The program includes a biweekly Privacy Review Club built around real upstream PRs. Before the session, participants check out the branch, build it, run relevant tests, read surrounding code and discussion, and prepare notes. In the session, they discuss motivation, implementation, trade-offs, edge cases, privacy implications, and test coverage. Participants take feedback upstream only when it is substantively useful.

Review progression moves from reproducing and testing a change, to explaining it, identifying missing tests or assumptions, providing useful upstream feedback, and eventually becoming a recurring independent reviewer. Participants who author substantial work are also expected to support others through review and validation.

## Measuring success

We are replacing headline PR-count targets with a contributor scorecard that distinguishes outputs from contributor maturity.

We track meaningful evidence across:

- authored and merged code;
- substantive review and review discussion;
- PR testing and validation;
- issue reproduction, investigation, and triage;
- tests, fuzzing, benchmarks, and documentation;
- privacy or protocol research;
- maintainer communication and response to feedback;
- repeat useful work in the same project;
- readiness for fellowships, grants, employment, mentoring, review, and maintenance.

Our north-star measure is the percentage of participants who remain meaningfully active in at least one Bitcoin privacy-related open-source project six months after structured training ends. We also check activity at three and twelve months.

Where practical, we will collect lightweight upstream feedback, centred on one practical question: **would this project like this contributor to continue working with it?**

## Fellowship bridge

Fellowships are not automatic graduation from the program and are not another class. They are selective funded time for people who have demonstrated technical depth, useful review judgment, reliability, initiative, good communication, response to feedback, and a credible path toward sustained involvement in one project.

This lets Code Orange serve as an Asia-focused sourcing and specialization pathway for long-term Bitcoin open-source contribution, complementary to Btrust's own fellowship and grant ecosystem.
